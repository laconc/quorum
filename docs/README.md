# Quorum documentation

Start with the contributor guide and reach for the rest as you need it.

| Read | When |
|------|------|
| [../AGENTS.md](../AGENTS.md) | **First.** The engineering standard, the non-negotiable invariants and what enforces each, the done-gate, and the things not to helpfully undo. |
| [design.md](design.md) | To understand *why* the system is shaped this way: the tenancy model, the process model, and the constraints the audience imposes. |
| [testing.md](testing.md) | The test taxonomy: what each layer proves, which harness catches what, and the rules that keep the suite honest. |
| [security.md](security.md) | The controls, the threat model, the post-quantum posture, and — just as importantly — what is *not* claimed. |
| [operations.md](operations.md) | Running it: deployment, the split-brain rule, backups, and the accepted risks. |
| [screenshots/](screenshots) | The visual record of the product, and how to regenerate it. |

The specification, the build plan, and the per-phase documents live outside this
repository and are provided when needed. **The design document is the decision
log** — it is amended in place rather than shadowed by a separate directory of
decision records.
